PatternBrowser → logs → table → optional export

Everything on this page is log-based, not span-based — no sdk-trace-web, no Zone.js. Every log flows through a LogRecordProcessor that feeds the live table below, the same role the RUM SDK's beforeSend plays in the main demo.

Sending to Datadog is off by default — this page never holds an API key. Turn it on from the Config tab.

Live tableThe beforeSend equivalent

A LogRecordProcessor registered ahead of the OTLP exporter renders every log into the table below before it's exported — the OpenTelemetry version of the RUM SDK's beforeSend.

Every log also prints to devtools via ConsoleLogRecordExporter — the same one the official getting-started guide uses. Toggle it from the Config tab.

 ExportWhy there's a proxy at all

Datadog's OTLP intake takes a real API key (dd-api-key header) — unlike the RUM SDK's public clientToken, that's not meant to ship in a browser bundle. So this page talks to your own small local proxy instead, which holds the key server-side.

Wire it up from the Config tab.

 LimitsWhat's not included

The same package also ships fetch/xhr instrumentations, but those two create spans, not logs — they'd need a full trace pipeline (sdk-trace-web) to do anything, which reverses the bundle-size tradeoff this lab is built around. Left out on purpose.

The "Fake backend call" button on the results screen still shows up via browser.resource_timing — just without trace correlation.
