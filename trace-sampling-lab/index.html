Trace Sampling Lab
Datadog RUM Training

Two RUM options decide which browser requests get a backend trace in Datadog: traceSampleRate and traceContextInjection. This lab fires real requests through the real RUM SDK, shows the headers it injected, and lets a simulated backend tracer react to them.

Training topics

KnobsThe two options

traceSampleRate (default 100) is the share of traced requests that RUM marks as sampled, meaning keep the trace.

traceContextInjection decides what happens to the rest:

  • 'all' — headers on every request, with x-datadog-sampling-priority: 0 on unsampled ones. The browser decides drop.
  • 'sampled' (the v6 default) — unsampled requests get no headers, so the backend's own sampler decides.

Both only apply to URLs in allowedTracingUrls, and only inside a tracked session.

 GotchaPer session, not per request

The SDK makes the trace decision with isSampled(session.id, traceSampleRate), a hash of the session ID. At traceSampleRate: 20, one session sends priority 1 on every request or on none. It doesn't send a 20% mix.

The 20% shows up across sessions. Send a batch, click New RUM session, and repeat. The Sessions table shows one outcome per session.

 NetworkReading the headers

Open devtools › Network, filter on api/order, and look at the request headers. With propagatorTypes: ['datadog', 'tracecontext'] a traced request carries:

  • x-datadog-trace-id, x-datadog-parent-id, x-datadog-origin: rum, x-datadog-sampling-priority
  • traceparent ending -01 or -00, and tracestate: dd=s:1;o:rum or dd=s:0;o:rum

The docked table shows what the backend actually received. Its last column checks whether RUM's resource event carries the same _dd.trace_id.

 BackendThe simulated tracer

There's no real APM service. A service worker (sw.js) answers ./api/ requests and does what a Datadog tracer does with incoming context:

  • an upstream decision arrived → honor it (keep on 1, drop on 0)
  • nothing arrived → start a new trace and sample it at DD_TRACE_SAMPLE_RATE

Real tracers also have error and rare samplers that can keep some priority-0 traces, and the Agent can set rates itself. Those aren't simulated here.

Traces linked to RUM depend only on sessionSampleRate × traceSampleRate. With 'sampled', the backend rate adds backend-only traces on top. With 'all', the browser drops them before the backend gets a say.
